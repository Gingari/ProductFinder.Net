# ProductFinder

**Меньше ручного поиска — быстрее готовая заявка.**

[![Release](https://img.shields.io/github/v/release/Gingari/ProductFinder.Net)](https://github.com/Gingari/ProductFinder.Net/releases/latest)
![Platform](https://img.shields.io/badge/platform-Windows%20x64-0078D4)
![.NET](https://img.shields.io/badge/.NET-10-512BD4)
![UI](https://img.shields.io/badge/UI-WPF-0078D4)

ProductFinder — Windows-приложение для подбора товаров по локальному каталогу и подготовки заявок.

Программа помогает обработать список из письма или Excel, найти подходящие позиции, проверить сомнительные совпадения и выгрузить артикулы с количеством.

**ProductFinder ускоряет работу специалиста, но не заменяет окончательную проверку товара.**

## Возможности

### Поиск и подбор

- Поиск по артикулу, названию и тексту строки заявки.
- Работа с локальным каталогом SQLite.
- Асинхронная загрузка и поиск без блокировки интерфейса.
- Кэширование подготовленного каталога.
- Отображение производителя и оценки совпадения.
- Проверка распознаваемых моделей, марок и характеристик.
- Цветовая индикация сомнительных результатов.
- Объяснение обнаруженных противоречий.
- Ручной выбор альтернативного товара.

### Обработка заявок

- Добавление товаров из результатов поиска.
- Быстрое добавление по артикулу.
- Вставка текста письма, списка товаров или скопированной таблицы.
- Выбор режима распознавания текста.
- Возможность запросить подтверждение при неуверенном подборе.
- Импорт Excel с выбором листа, строки заголовка и колонок.
- Предварительный просмотр и выбор строк перед импортом.
- Обработка повторяющихся позиций при импорте.
- Редактирование количества и удаление выбранных строк.
- Выгрузка артикула и количества в Excel.

### Дополнение каталога

- Поиск товара на ЭТМ из любой подходящей строки заявки.
- Изменение запроса перед поиском.
- Выбор товара из результатов.
- Получение названия, артикула производителя и производителя из карточки.
- Проверка данных перед записью.
- Обработка существующего артикула.
- Резервное копирование перед изменением каталога.
- Обновление строки заявки после подтверждения.

## Требования

### Готовая программа

- Windows x64; рекомендуются актуальные версии Windows 10 или Windows 11 с поддержкой .NET 10.
- Каталог товаров `products.db`.
- Доступ на запись в пользовательскую папку приложения.
- Интернет для работы с ЭТМ и возможной загрузки браузерного компонента.

**Самодостаточная сборка включает .NET.** Отдельная установка SDK или Visual Studio для её запуска не нужна.

Основной поиск по уже загруженному локальному каталогу не требует подключения к ЭТМ.

### Браузерный компонент

Edge не обязателен.

Приложение использует доступный Chromium, Google Chrome или Edge. Если подходящий компонент не найден, предлагается загрузка Chromium с согласия пользователя.

По умолчанию используется режим **без видимого окна браузера**. Проверки сайта могут потребовать перехода в видимый режим.

### Разработка

- Windows.
- .NET 10 SDK.
- Visual Studio с поддержкой .NET 10 и компонентами разработки WPF либо .NET CLI.
- Доступ к NuGet для восстановления зависимостей.

## Установка и первый запуск

1. Откройте [Releases](https://github.com/Gingari/ProductFinder.Net/releases/latest).
2. Скачайте архив готовой Windows-сборки. Для первого запуска рекомендуется **full**.
3. Распакуйте **весь архив** в отдельную папку.
4. Если каталог не включён в архив, положите исходную базу `products.db` рядом с `ProductFinder.exe`.
5. Запустите `ProductFinder.exe`.
6. Дождитесь загрузки каталога.

> Не переносите только EXE и не удаляйте библиотеки или служебные папки из публикации. Даже компактная сборка может содержать обязательные дополнительные файлы, в частности компоненты Playwright.

При первом обычном запуске создаётся рабочая копия каталога. Последующие изменения через ЭТМ сохраняются в эту копию.

## Работа с заявкой

### Поиск вручную

1. Введите артикул, название или строку заявки.
2. Нажмите **«Найти товар»**.
3. Проверьте результаты и предупреждения.
4. Добавьте выбранную позицию двойным щелчком.
5. Укажите количество.

Для быстрого добавления известного артикула используйте блок **«Добавить по артикулу»**.

### Заявка из текста

1. Нажмите **«Вставить заявку»**.
2. Вставьте текст или загрузите его из буфера обмена.
3. Выберите режим распознавания.
4. При необходимости включите вопрос при неуверенном совпадении.
5. Нажмите **«Разобрать и добавить»**.
6. Проверьте полученный список.

### Заявка из Excel

1. Нажмите **«Импорт Excel»**.
2. Выберите файл.
3. Укажите лист и строку заголовка.
4. Настройте колонки артикула, названия и количества.
5. Проверьте предварительный просмотр.
6. Отметьте нужные строки и подтвердите импорт.

### Подготовка результата

- Проверьте сомнительные и ненайденные позиции.
- Двойным щелчком выберите другой вариант, если это необходимо.
- Дополните товар через ЭТМ.
- Проверьте количество.
- Нажмите **«Выгрузить в Excel»**.

Выгрузка содержит **артикул и количество**.

## Оценка совпадения

| Цвет | Оценка | Как использовать |
| --- | --- | --- |
| 🔴 Красный | Ниже 50% | Требуется внимательная проверка; возможны явные противоречия. |
| 🟡 Жёлтый | 50–79% | Совпадение неуверенное, позицию следует проверить. |
| 🟢 Зелёный | От 80% | Высокое сходство по алгоритму, но не гарантия соответствия. |

Дополнительные признаки необходимости проверки учитываются при отображении предупреждений.

**Процент — эвристическая оценка поиска, а не вероятность правильного подбора.**

### Что проверяется

Для поддерживаемых шаблонов анализируются:

- модель и серия;
- производитель или марка;
- мощность;
- цветовая температура;
- степень защиты IP;
- размер;
- ряд электрических характеристик.

При обнаружении противоречия оценка снижается, а причина отображается в подсказке.

Например, одинаковые мощность и цветовая температура не делают модели **ДБО 5005** и **ДБО 0202** одним товаром.

### Чего оценка не гарантирует

- Полной технической взаимозаменяемости.
- Проверки характеристик, отсутствующих в тексте.
- Распознавания всех существующих серий и обозначений.
- Правильного подбора без участия специалиста.

Отсутствие обычной характеристики в кратком названии само по себе не означает противоречие.

Ручной выбор товара не скрывает уже обнаруженное предупреждение.

## Дополнение каталога через ЭТМ

Допарсинг доступен для строки заявки с исходным текстом или названием — в том числе для уже найденного товара.

### Порядок действий

1. Нажмите **«Допарсить»**.
2. Проверьте или измените поисковый запрос.
3. Нажмите **«Найти на ЭТМ»**.
4. Выберите подходящий товар.
5. Нажмите **«Отпарсить»**.
6. Проверьте название, артикул производителя и производителя.
7. Нажмите **«Сохранить и добавить»**.

**Поиск и чтение карточки не изменяют каталог.**

Запись выполняется только после подтверждения.

### Если артикул уже существует

Можно:

- оставить существующую запись и использовать её в заявке;
- заменить выбранную запись данными ЭТМ;
- отменить действие.

Остальные найденные дубликаты не заменяются автоматически.

Количество и исходная строка заявки сохраняются при дополнении товара.

### Фоновый и видимый режимы

По умолчанию включён режим без окна браузера.

Если сайт требует проверки или взаимодействия, используйте **«Открыть браузер»**.

Приложение использует отдельный профиль:

```text
%LOCALAPPDATA%\ProductFinder\EtmBrowser
```

Обычный пользовательский профиль Chrome или Edge не используется.

### Ограничения сайта

Работа парсера зависит от:

- доступности ЭТМ;
- текущей разметки сайта;
- сетевых ограничений;
- проверок и ограничений доступа со стороны сайта.

Приложение не выполняет обход запретов доступа.

Если пользователь подтвердил загрузку Chromium, отмена ожидания поиска не останавливает уже начатую загрузку компонента.

## Каталог и хранение данных

### Формат каталога

Каталог — база SQLite с таблицей `catalog`.

| Колонка | Содержимое |
| --- | --- |
| `Артикул` | Артикул товара |
| `Название товара` | Наименование |
| `Производитель` | Производитель |

Загрузчик поддерживает исходную базу без колонки `Производитель`. При сохранении через ЭТМ эта колонка при необходимости добавляется.

### Рабочая база

При обычном запуске рабочая копия находится здесь:

```text
%LOCALAPPDATA%\ProductFinder\Catalog\products.db
```

Исходная база копируется туда один раз.

> Замена `products.db` рядом с EXE не перезаписывает существующую рабочую базу.

При намеренной замене рабочего каталога закройте приложение и сначала сохраните резервную копию.

Если путь базы явно передан в коде, используется указанный путь.

### Резервные копии

Перед вставкой или заменой записи создаётся резервная копия:

```text
%LOCALAPPDATA%\ProductFinder\CatalogBackups
```

При частом изменении каталога резервные копии могут занимать заметное место. Удаляйте старые копии только после проверки актуальной базы.

### Сохранение заявки

Рабочая база и её резервные копии **не сохраняют текущую заявку**.

В этой версии список заявки находится в памяти. Перед закрытием приложения рекомендуется выгрузить результат в Excel.

### Подготовка каталога

Базы `.db` исключены из Git.

В текущем проекте файл `ProductFinder/products.db` подключён для копирования при сборке. Перед сборкой положите туда исходный каталог.

Это отдельное требование подготовки данных, а не часть установки .NET.

### Сборка приложения

Команды из корня репозитория:

```powershell
dotnet restore .\ProductFinder\ProductFinder.csproj
dotnet build .\ProductFinder\ProductFinder.csproj -c Release --no-restore
```

Для сборки приложения требуется **.NET 10 SDK**.

### Публикация обычной сборки

```powershell
dotnet publish .\ProductFinder\ProductFinder.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=false `
  -p:PublishTrimmed=false `
  -p:DebugType=None `
  -p:DebugSymbols=false `
  -o .\artifacts\ProductFinder-win-x64-full
```

### Публикация компактной сборки

```powershell
dotnet publish .\ProductFinder\ProductFinder.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:PublishTrimmed=false `
  -p:DebugType=None `
  -p:DebugSymbols=false `
  -o .\artifacts\ProductFinder-win-x64-compact
```

Компактная сборка не обязательно состоит из одного файла.

Не удаляйте дополнительные файлы, оставленные публикацией, особенно компоненты Playwright. Перед выпуском проверяйте обе сборки отдельно.

Готовые архивы публикуются в **GitHub Releases**, а не добавляются в историю Git.

### Тесты

Папка `Tests` содержит проверки нормализации, поиска и рабочих сценариев.

Тестовый проект пока требует актуализации:

- используется отдельная версия зависимостей;
- необходима тестовая база `fixture.db`, не включённая в репозиторий;
- часть проверок отражает предыдущую версию поведения поиска.

Наличие тестов в репозитории не означает, что весь набор сейчас проходит из чистого клона.

При обновлении тестов следует сохранять регрессии для ранее корректного подбора и добавлять реальные проблемные примеры.

## Известные ограничения

- Автоматического восстановления незавершённой заявки пока нет.
- Перед выгрузкой пользователь должен проверить сомнительные и ненайденные строки.
- После сохранения через ЭТМ каталог перечитывается; на больших базах это может занять время.
- Поиск использует эвристики и не заменяет техническую экспертизу.
- Работа ЭТМ зависит от доступности и разметки сайта.
- Компактная сборка может требовать дополнительных файлов рядом с EXE.
- Тестовый набор пока не полностью синхронизирован с текущей версией приложения.

## Частые вопросы

### Нужен ли интернет для обычного поиска?

Для поиска по локальному каталогу — нет.

Интернет нужен для работы с ЭТМ и возможной загрузки Chromium.

### Нужно ли устанавливать .NET?

Для опубликованных самодостаточных сборок — нет.

Для разработки и сборки из исходников нужен .NET 10 SDK.

### Обязательно ли устанавливать Edge?

Нет. Приложение может использовать Chromium или Chrome.

### Почему новый каталог рядом с EXE не появился в приложении?

Если рабочая база уже существует в `%LOCALAPPDATA%`, приложение продолжает использовать её.

Замена исходного файла не перезаписывает рабочий каталог автоматически.

### Почему товар получил низкую оценку, хотя название похоже?

Причиной может быть другая модель, марка или распознаваемая характеристика. Посмотрите объяснение в подсказке.

### Почему при запуске компактной версии нужны дополнительные файлы?

Объединение библиотек в EXE не отменяет необходимости служебных компонентов, используемых парсером.

Распаковывайте весь архив и сохраняйте его структуру.
