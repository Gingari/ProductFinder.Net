# ProductFinder — Excel и вставка заявки из текста

Готовый WPF-проект на .NET 8 / C# 12. Все три кнопки подключены к рабочим командам.
Код разделён на Models, Services, ViewModels, Views, Infrastructure и Resources.
Исходники C# и XAML без комментариев.

## Установка новой версии

1. Закройте приложение и сохраните резервную копию своего проекта и products.db.
2. Распакуйте архив в новую папку. Не добавляйте файлы в старый проект вручную.
3. Скопируйте свой products.db в ProductFinder/Resources/products.db.
4. Откройте ProductFinder.sln, дождитесь восстановления NuGet и нажмите F5.

Если база лежит в ProductFinder/products.db, этот вариант также поддерживается.
Если существуют обе базы, приоритет имеет Resources/products.db. Настройки копирования
обеих папок уже находятся в .csproj. Каталог открывается только для чтения.
Вашей рабочей базы в архиве нет; Tests/fixture.db содержит искусственные данные.

Включено исправление OneWay для прогресса: доступные только для чтения свойства
ViewModel не используются в двусторонних привязках. Повторно править эту строку не нужно.

## Выгрузка в Excel

- Добавьте позиции в заявку, затем нажмите «Выгрузить в Excel».
- Формат .xlsx, лист «Товары», колонки «Артикул» и «Количество», как в Python.
- Выгружается весь список, включая ненайденные/ручные позиции, как раньше.
- Артикул сохраняется текстом: ведущие нули и строки вида =1+1 не превращаются в числа/формулы.
- Количество — числовая ячейка. Есть заголовок, фильтр и закреплённая первая строка.
- Перед выгрузкой завершается редактирование количества. Некорректный ввод нужно исправить.
- Запись идёт во временный файл; готовый файл заменяет выбранный только после успешной записи.

## Импорт Excel

Поддерживаются .xlsx, .xlsm, .xls. Microsoft Excel устанавливать не требуется.
Макросы не исполняются, формулы читаются по сохранённым значениям, как data_only в Python.
Если формула не имеет сохранённого результата, предварительно пересчитайте и сохраните файл в Excel.

1. Нажмите «Импорт Excel», выберите файл и лист.
2. Заголовок определяется автоматически среди первых 30 строк.
3. Можно указать строку заголовка от 1 до 100 и нажать «Применить».
4. Выберите колонки артикула, названия и количества. Название можно не использовать.
5. Проверьте предварительный список. Артикул, название и количество можно исправить.
6. Отметьте нужные строки и нажмите «Импортировать выбранные».

Фильтр ищет по артикулу, названию и исходной строке. Выделить/снять/инвертировать
действует только на видимые строки. Сам фильтр НЕ снимает отметки со скрытых строк;
при подтверждении импортируются все отмеченные, как в Python.

Пустое/неразбираемое/неположительное исходное количество по умолчанию превращается в 1,
как в Python — проверьте предварительный список. Дробные значения округляются как Python round
(например, 10.5 → 10, 11.5 → 12). После ручного исправления требуется положительное целое число.
Повторные строки заголовка по умолчанию не отмечаются.

Дубли объединяются в пределах одного импортируемого блока по нормализованному артикулу,
или по названию, если артикула нет. Количества суммируются. Уже существующий список не склеивается.
Поиск в каталоге при импорте строгий, без нечёткого подбора по названию:
найденные позиции зелёные, ненайденные сохраняются красными. Итоговый отчёт показывает счётчики.

Редактор количества поддерживает положительные Int32 (до 2147483647); ручное добавление
и диалог количества по-прежнему ограничены 100000. Переполнение суммы отклоняет весь импорт,
не оставляя частично добавленных строк. Листы с прямоугольником данных более 5 миллионов ячеек
отклоняются с понятным сообщением, чтобы не исчерпать память из-за лишнего форматирования.

## Вставка заявки

Нажмите «Вставить заявку», вставьте текст через Ctrl+V или кнопку «Из буфера».

- Авто: сначала артикул, затем подбор по названию; распознаётся скопированная таблица прайса.
- Только артикулы: строгий поиск, ненайденные строки можно пропустить или добавить красными.
- Только названия: без прямого поиска артикула, подбор по токенам и характеристикам.
- Таблица прайса: артикул + наименование + количество, объединение дублей, строгий поиск.

Распознаются «3 шт», «шт. 3», количество на отдельной строке, строки с дефисом,
HTML-переносы и приветствия. Уверенные совпадения добавляются автоматически.
При неуверенном совпадении можно включить окно выбора. «Отмена» в окне выбора
сохраняет лучший неуверенный вариант жёлтым, как в Python, а не отменяет весь разбор.
Ненайденные позиции сохраняются красными; строки с распознанным нулевым количеством пропускаются с отчётом.
Двойной клик по строке заявки позволяет выбрать другой вариант позже.

Общий счётчик добавленных строк исправлен: учитывает также уверенные и неуверенные совпадения,
которые в Python добавлялись, но не всегда включались в счётчик сообщения.

## Фоновая работа

Чтение файлов, выгрузка и подбор выполняются в фоне. Зависимые действия временно отключаются.
В статусе отображается операция, рядом появляется «Отменить». Добавление блока происходит
после успешной подготовки: отмена не оставляет половину импортируемой заявки.
Открытие самой книги библиотекой может завершаться не мгновенно по отмене; UI не блокируется.
Обычная отмена выбора файла/редактора не меняет заявку.

При закрытии приложения заявка пока не сохраняется между запусками, как в исходном Python.
Сначала выгрузите её в Excel, если хотите сохранить.

## Зависимости

Microsoft.Data.Sqlite 8.0.31 и NPOI 2.7.6 уже указаны в .csproj.
NPOI выбран с лицензией Apache-2.0; обновлять его до 2.8.x автоматически не нужно,
у этой ветки другое лицензионное соглашение. SqlClient не используется.

## Проверки

Сборка WPF выполнялась в Linux с EnableWindowsTargeting=true. Ядро и сценарии ViewModel
исполнялись на .NET 8. Окна WPF непосредственно в Windows здесь не запускались;
после установки проверьте диалоги, редактирование таблицы и работу на ваших реальных файлах.
Макеты новых окон проверены по размерам, но они не заменяют запуск WPF.

Проверены:
- Предыдущие тесты каталога, поиска, количества, замены вариантов, удаления и кэша.
- Сравнение с Python: 23 текста заявки и 20 значений количества Excel.
- Чтение XLSX, XLS и XLSM; листы, автоопределение колонок, сохранённые формулы, правки списка.
- Дубли, строгий артикул, ненайденные позиции, все режимы вставки и окно неуверенного выбора.
- Выгрузка: структура, типы ячеек, ведущие нули, формулоподобный текст, отмена и атомарная запись.
- Команды ViewModel и отмена разбора без частичного добавления.
- Путь к базе в Resources и корне; структурная проверка OneWay у прогресса.
- Созданный Excel открыт, проверен и отрисован; предупреждение аудита о 001234 как тексте намеренное:
  это артикул, а не числовое значение.

Запуск проверок из корня решения:

dotnet run --project Tests/CoreTests.csproj
